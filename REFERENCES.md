# References

These sources support the repository's writing rules. Each skill cites the references
specific to its document type. This file keeps the full list in one place. Start with
the five entries below.

## Starter set (if you read five things)

1. Daniele Procida, **Diátaxis** (diataxis.fr). Distinguishes tutorials, how-to guides,
   reference, and explanation. Provides the structure used by `tech-docs`.
2. Barbara Minto, **The Pyramid Principle**. Presents the answer before its supporting
   argument.
3. **Google Technical Writing courses** (developers.google.com/tech-writing). Free,
   concise courses that establish a shared baseline.
4. Joseph Williams, **Style: Lessons in Clarity and Grace**. Explains sentence-level
   clarity, including characters as subjects and actions as verbs.
5. Michael Nygard's **ADR essay**. Provides foundations for decision records.

## Writing craft (applies everywhere)

- William Zinsser, *On Writing Well*. Simplicity, clutter, and warmth.
- Strunk and White, *The Elements of Style*. Concise rules for composition and revision.
- Joseph Williams, *Style: Lessons in Clarity and Grace*. Characters as subjects and
  actions as verbs.
- Steven Pinker, *The Sense of Style*. Covers evidence-based style and the curse of
  knowledge: forgetting that the reader lacks the author's context.
- Richard Lanham, *Revising Prose*. The Paramedic Method for reducing unnecessary
  passive voice and noun strings.

Applied in: the constitution and `natural-writing`, covering the curse of knowledge,
plain style, sentence clarity, and revision (Williams, Lanham, Zinsser, Strunk and
White).

## Technical and engineering writing

- Google Technical Writing courses (developers.google.com/tech-writing). Practical
  guidance for developer documentation. Backs `tech-docs`.
- Google Developer Documentation Style Guide. Terminology, tone, formatting decisions.
  Backs `tech-docs`.
- Microsoft Writing Style Guide. Strong on warm, second-person voice and accessibility.
  Backs `tech-docs`.
- Daniele Procida, Diátaxis (diataxis.fr). The four-mode framework used by `tech-docs`.
- Write the Docs (writethedocs.org). A documentation community and source of practical
  guidance. Backs `tech-docs`.
- Andrew Etter, *Modern Technical Writing*. Short, opinionated, docs-as-code. Backs
  `tech-docs`.

## Decision records, RFCs, and design docs

- Michael Nygard, "Documenting Architecture Decisions." The original ADR. Backs `adr`.
- Malte Ubl, "Design Docs at Google" (industrial-empathy.com). Backs `tech-design`.
- Oxide Computer RFD process (rfd.shared.oxide.computer, RFD 1). A public example of an
  RFC process. Backs `tech-design`.
- The IETF and Rust RFC traditions, for the structure and tone of proposal docs.
- Gergely Orosz, "How to write engineering design docs" (The Pragmatic Engineer).
  Practical guidance for design documents. Backs `tech-design`.
- Will Larson, on writing technical specs and design docs (lethain.com). Backs
  `tech-design`.

## Review and feedback

- Google's engineering practices, "How to do a code review" (google.github.io/eng-practices).
  High-signal, respectful, substance-first review. Backs `critique` and `arch-review`.
- Kim Scott, *Radical Candor*. Care personally and challenge directly.

## Diagrams and visual explanation

- Simon Brown, the C4 model (c4model.com). A leveled way to diagram architecture. Backs
  `arch-review` and `tech-design`. Author diagrams as code in a format supported by the
  target repository and publishing system.
- Edward Tufte, *The Visual Display of Quantitative Information*. Principles for clear
  charts and data displays.

## Voices worth studying for style

- Julia Evans (jvns.ca). Makes difficult technical subjects approachable. Backs
  `tech-blog`.
- Dan Luu (danluu.com). Rigorous, plain, data-driven analysis. Backs `tech-blog`.
- Martin Fowler (martinfowler.com). Explaining architecture clearly and durably. Backs
  `tech-blog`.
- Will Larson (lethain.com). Engineering strategy and org writing.
- Charity Majors (charity.wtf). Opinionated and vivid on ops and observability. Backs
  `tech-blog`.
- Joel Spolsky (Joel on Software). Uses concrete openings to build persuasive technical
  essays. Backs `tech-blog`.
- Stripe's documentation and engineering writing. Useful examples of clear structure
  and precise technical explanation. Backs `tech-docs` and `tech-blog`.
